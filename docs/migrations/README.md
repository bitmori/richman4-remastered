# 原生迁移记录

目标是用可读的 C++ 实现完整游戏，在 Mac ARM64 和 Android ARM64 共用引擎。**2026-10-05 按用户要求暂停。** 当前为可运行对局的 Mac 原生原型；用户指出 UI 复刻不完整、细节缺失，整体体验没有验收通过。下表记录模块实现与证据，不是产品完成清单。当前状态、UI缺口、测试中断和恢复优先级以 [交接记录](../STATUS.md) 为准。

## 代码边界

- `include/rich4`、`src`：平台无关值类型和规则；无 Windows 头文件、内联汇编、操作系统句柄和文件指针重定位。
- `tools/native_game.cpp`：SDL3原生游戏与无桌面输入回放；音频/文字/按钮不直接修改规则状态。
- `tools/resource_viewer.cpp`：SDL3 显示后端和资源查看器；保持 640×480 逻辑画面与最近邻缩放。
- `tests`：可随源码分发的合成用例，以及读取本机原版金标的比较器。
- `tools/oracle`：仅用于测试的 Win32 适配器，原生运行时不会链接、调用或加载它们。
- `tools/playability`：原版操作/观察适配器和平台无关的存档状态检查 CLI；原生引擎不依赖这里的 Win32 测试代码。
- `.local/upstream`、`.local/oracle`、`artifacts`：原参考源码、个人素材和本机验证结果，不进入 Git。

去掉 32 位架构依赖不等于删除 `uint32_t`。文件、像素和原版规则仍需要明确的 8/16/32 位字段；被删除的是“整数就是指针”“磁盘结构与宿主结构相同”“依靠有符号溢出或越界访问”等假设。

默认保持正常输入的原版结果，包括不符合现代直觉的行为：2100 年闰年、打包日期中的 2 月 31 日、byte 库存回绕、地租低 32 位乘积、SPR 的索引透明色、地面负步长的分数部分。损坏输入的内存破坏行为由明确异常替代，逐项记录在对应文档。

原生 C++ 使用仓库 `.clang-format` 统一四空格缩进及多行控制流，避免把迁移后的规则压成难以检查的一行。格式工具固定为 clang-format 20.1.8，可通过 `uv tool run --from clang-format==20.1.8 clang-format` 调用；格式修改与规则变更分别提交。原始汇编参考和机器采集结果不由格式工具改写。

## 后续验收与平台工作

- 暂停期间不自动执行以下事项；用户恢复后先按原版逐页补齐 UI 和交互，独立验收视觉完整性与实际体验。
- 19场回放各自通过（含八地图30天、合成胜利），但卡片覆盖汇总失败；20场复验只完成5场即中断。恢复后需完整新批次，不能拼接局部报告。90天单局证据也不代表所有分支完成。
- 有明确来源但尚无EXE差分的模块继续增加原版对照；图形仍未宣称整帧或计时动画逐像素一致。
- 原版AVI当前是23个占位文件；待正式版素材到位后完成过场、跳过和同步验证。
- Android仍需SDL Activity、素材导入、触摸、生命周期、音色库和APK；核心运行验证不代表Android应用已可玩。

## 后续每次迁移的方法

1. 写清原入口、调用者、状态字段和正常输入范围，先建立原版结果采集。
2. 用具名类型重写；明确小端序、位宽、舍入、数组边界和所有权，避免逐条翻译寄存器。
3. 使用同一输入，比较返回值、变更后的状态或像素；单测补充正常资源无法覆盖的边界。
4. 运行 Mac 内存/未定义行为检查及 Android ARM64 同一组测试。
5. 在本目录新增记录，区分已验证、仅实现和未迁移；按用户要求在本地 `main` 做有意义的增量提交。

完整回放必须记录多次播种事件：原版会在启动、读档完成和每日股票更新前重新播种。只固定初始 seed 或只对比截图都不足以证明整局一致。
