# 003 — 软件绘图与 SDL3 显示

本模块把图片展开、裁剪、透明色和像素转换移到独立 C++20 核心。SDL3 只负责创建窗口、事件和最终纹理呈现；游戏资源不交给平台 API 解释。`rich4-resource-viewer` 是开发用资源查看器，尚未实现可玩的主菜单或回合。

## 来源与接口

固定上游提交 `ec7d70e693059d1e781d9d1cc2ad7f36d360d39e`：

| 原函数/文件 | 新接口 | 保持的规则 |
| --- | --- | --- |
| `csrc/mkf/mkf.c` / `update_pixels`, 原 EXE `0x451801` | `rgb555_to_rgb565` | 位操作逐值一致，绿色第六位保持 0 |
| `asm/rich4_drawing.c`, `0x455b3a` | `blit(..., opaque)` | 先减图片原点，再按四边裁剪；行优先复制 |
| 同文件，`0x455c52` | `blit(..., source_key)` | SMP 的原始像素值 0 不绘制 |
| `asm/rich4_drawing_utils2.asm`, `0x456512`、`0x45663e` | `decode_frame` + `blit` | SPR 按调色盘展开；透明绘制跳过索引 0 |
| DirectDraw 窗口呈现 | `tools/resource_viewer.cpp` | 640×480 逻辑画面、最近邻缩放、保持长宽比 |

实现：`include/rich4/graphics.hpp`、`src/graphics.cpp`。`Image` 使用向量管理像素，不把 32 位文件字段重定位成宿主指针。`Rect` 右边和下边不含在绘制范围内。

原始颜色是 RGB555。原版 RGB565 转换等于 `(c & 31) | ((c << 1) & 0xffc0)`；因此 `0x7fff` 转成 `0xffdf`，不能擅自补满绿色位。SDL 显示端再把各通道线性展开成 ARGB8888；显示端不参与原始 16 位像素对照。

SPR 的透明规则需要额外保存每像素的不透明标记：`palette[0]` 可以非零，`palette[1]` 也可以为零，透明性始终取决于**源索引**。只把 SPR 展开成颜色，再按颜色零值判断，会改变原游戏行为。

## 处理的异常输入

- 显式检查尺寸、像素存储长度和 mask 长度；每张图片上限 32 Mi 像素。
- 四边同时相交，使用 64 位坐标中间值，避免旧辅助函数在源图跨越目标两边时越界。
- 同一 `Image` 向自身复制时先复制源像素，定义稳定的重叠行为。原版中可能依赖复制方向的自重叠调用未作为等价域。
- 不实现旧函数绘制返回值；当前公开接口是 `void`，只承诺已验证输入的像素结果。

安全检查与自重叠规则属于明确的边界修正，不以它们声称复现原程序的内存破坏行为。

## 验证

`graphics_tests` 覆盖原点、四边裁剪、双边超出、透明色、自复制、极端坐标、像素格式、SPR 索引透明和 SMP 小端读取。Mac ARM64 的 ASan/UBSan 测试通过。

本机全部七个 MKF 实际解码并展开：720 个图形资源、13,034 帧，全部尺寸与像素字节数有效。其中 SPR 为 653 个资源 / 11,837 帧，SMP 为 67 个资源 / 1,197 帧。报告在 `artifacts/native-graphics-corpus.json`，商业素材和导出图片不纳入 Git。

原版 EXE 对照工具见 [000-oracle.md](000-oracle.md)。RGB565 比较覆盖 65,536 个输入；基础 blit 比较覆盖 1,344 组位置、原点和透明模式。SPR 的独立原版案例另外覆盖“非零调色盘槽 0”和“零颜色非零索引”。最终执行记录见 [validation.md](validation.md)。

原生 SDL3 Mac 窗口已经实际启动并显示 `Data.mkf[1]` 主菜单背景，资源翻页、帧切换和退出由 SDL 事件驱动。这个静态素材窗口不代表菜单交互、文字渲染、地图相机、动画时序或游戏逻辑已经迁移。
