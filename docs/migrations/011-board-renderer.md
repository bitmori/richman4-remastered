# 011 — 原版视角地图、建筑与人物场景绘制

状态：已实现无 SDL、Windows、32 位指针依赖的 C++20 CPU 场景绘制。台湾地图及全部八张地图均使用原始 GND/SPR/SMP 资源，支持八个相机方向、道路图标、人物、静止道具、地产、设施、上市企业和景观。输出为 `graphics::Image`，可供 SDL 或其它平台显示。

这是一项真实地图场景迁移；不包含完整游戏规则。相机与场景组合尚未获取原版 EXE 整帧金标，不能把本次原始资源截图等同于整帧逐像素一致的证明。

## 来源与资源选择

参照上游 `mytbk/rich4` 提交 `ec7d70e693059d1e781d9d1cc2ad7f36d360d39e`：

- `asm/rich4.asm`：`0x407a2c` 子 tile 坐标；`0x40829d` 地面与对象绘制；`0x409a23` 世界坐标投影；`0x40b93b` 人物资源选择。
- `asm/rich4_load_map.asm`：地图、地产、设施、景观和道具资源编号。
- 投影角点表 `0x46ccf0`、地面遍历表 `0x473610`、小数坐标基底 `0x474910`。

派生实现保留 Iru Cai 的来源说明及 `GPL-3.0-or-later`。商业资源和原版 EXE 不纳入仓库。运行时只读取用户提供的 `MAP.MKF` 和 `DATA.MKF`，不读取 EXE、ASM 或 Wine 内存。

全局地图编号为 `stage * 4 + map`，范围 0–7。资源映射如下：

| 内容 | 原始资源 |
|---|---|
| 地面 / 地图记录 | MAP `2 * map_id` / `2 * map_id + 1` |
| 道路位置标记 | MAP `0x18`，节点 `+0x22` 字段减一为帧号 |
| 空地所有权标记 | MAP `0x19`，帧号为拥有者的角色编号 |
| 普通房屋等级 1–5 | MAP `0x27 + map_id * 5 + level - 1` |
| 连锁店 | MAP `0x4f + map_id` |
| 现代地图设施 | MAP `0x57..0x67` |
| 时空地图设施 | MAP `0x68 + local_map * 17` 起的 17 项 |
| 企业和景观 | MAP `0x26 + record.sprite_index`；保留原共享资源表的前 24 槽映射 |
| 人物常规姿态 | DATA `0x80 + character * 21 + traffic_method * 3 + pose` |
| 特殊角色槽 4–7 | DATA `0x16c + slot * 4 + pose`；静止、走路、水面、梦游 |
| 机器娃娃槽 8 | DATA `0x209` 静止、`0x20a` 行走 |
| 静止道具 | DATA `0x18c + kind - 1` |

人物方向为 `(direction + 8 - camera_rotation) & 7`，每个方向使用 `frame_count / 8` 帧。建筑、企业、景观使用 `(8 - record.direction - camera_rotation) & 7`。交通方式覆盖步行、机车、汽车、工程车；常规姿态覆盖静止和行走。

## 可移植接口与坐标规则

`Renderer(asset_directory, map_id)` 拥有地图和按需解码的图片缓存；`Scene` 是只读的玩家、道具、土地和设施视图。游戏状态由调用者拥有，渲染器不会推进回合、更新地图记录或随机数。

```cpp
rich4::board::Renderer renderer(asset_directory, 0);
rich4::board::Camera camera{{active_player.x, active_player.y}};
renderer.render(framebuffer, scene, camera);
```

默认窗口裁剪为 `[0,40,440,480)`，即原版 440×440 的棋盘区域；相机中心投影到 `(220,260)`。SDL 应保持 640×480 逻辑画布后整体缩放。边栏和工具栏由应用绘制。

世界坐标每 32 个单位对应一块地面。必须保留原版的不对称整数舍入：

1. 世界和相机坐标各自向下除以 32，再求相对 tile；范围超出 `[-14,14]²` 的对象直接剔除。
2. 整数 tile 角点来自 8×29×29 个原始 `(x,y)` 值。该表含历史浮点预计算留下的 1–2 像素差异，不可用新的理想矩阵替换。
3. 低五位坐标分别乘以原版四项有符号基底，每项单独向下除以 32；不是相加后统一舍入。
4. 对象位置为 `screen_center + grid_point + camera_fraction - object_fraction`。
5. 地面四角按原始顺序组成四边形，使用模块 007 的定点光栅化器；按原版每视角最多 304 个 tile 偏移遍历。地图外纹理为全零索引，仍经原版地面调色盘绘制。

`scripts/generate_board_projection.py` 可从 GPL 上游 ASM 重建具名常量表：

```sh
python3 scripts/generate_board_projection.py .local/upstream/asm/rich4.asm
```

生成文件 `src/board_projection_tables.inc` 标明三个原地址及原始数据 SHA256，数据共 31,808 字节。没有把宿主指针、汇编指令或平台 ABI 留在渲染实现中。

## 场景排序、颜色及资源安全

地面之后先绘道路标记，再建立对象绘制队列。队列插入顺序沿用人物、道具、土地、设施、企业、景观。深度保留原版 signed16 键 `(screen_y << 4) | category`，普通人物类别为 12，当前人物为 13。相同高度的当前人物会盖住其它人物。完全相同的键采用稳定顺序，替代不同 C 运行库 `qsort` 的未规定平局顺序。

地产所有权仅替换 SPR 调色盘第 255 项；索引 0 的透明规则独立保留。缓存以资源、帧、颜色为键，不原地修改 MKF 解压结果，避免一家房屋染色影响另一家。尚未出现在玩家视图中的拥有者使用四种明确的备用颜色；正常应用应提供全部拥有者和原版角色颜色。

磁盘表按小端字段读取，记录数、偏移、哨兵和边界经过检查。原版 DAT 的第零项继续作为哨兵。精灵帧越界、非法角色/交通方式/设施类型、无效相机和不匹配画布抛出异常；没有静默跳过损坏资源。移动中的游戏状态由值视图传入，不依赖存档中的 32 位地址。

## 验证与当前局限

本机 macOS ARM64 的 C++20 + AddressSanitizer + UndefinedBehaviorSanitizer 测试已通过：

- 原版查表选点、负坐标向下舍入、32 个子 tile 小数位置、全部 8 个视角、相机邻域边界、极端整数值和非法输入。
- 使用原版资源生成 15 张场景帧：台湾 8 个视角及其它 7 张地图，共 190 次精灵绘制。
- 顶栏、侧栏像素保留，棋盘区域真实填充；两名同位置人物的原始帧选择、锚点和当前玩家优先遮挡，与独立解码/合成的预期整张画布一致。
- 底层模块 003 的精灵绘制与模块 007 的四边形绘制已分别通过原版 EXE 像素金标；本模块复用这些实现。相机/组合层目前使用源码表和独立场景测试，未冒充新的 EXE 整帧金标。
