# 017 — 商店与魔法屋

本模块将原商店交易与魔法屋的对象选择、效果改写为 `services.hpp/.cpp` 中的平台无关规则。`GameSession` 负责串接可暂停的选择，SDL 界面只提交选择。

## 原始入口与保留行为

来源为已固定版本 upstream 的 `rich4_shop.asm`、`rich4_magic_house.asm`、`rich4.asm` 中 `0x431842`、`rich4_card_table.c`、`rich4_tool_table.c`、`rich4_card_utils_2.asm` 和 `rich4_tool_utils.c`。

- 卡片和道具价格、名称、AI 偏好来自原表。卡片 ID 为 1–30，道具 ID 为 1–13；普通商店仅出售前八种道具。
- 人类商店货架先抽 `rand()%10+6` 张卡。每张按剩余供应量加权抽取，从临时供应量扣除，真正买入才减少世界库存。货架在整次访问中保持，不因界面重绘重新抽取。
- 自有商业商店先随机赠卡或道具；赠品与普通货架分别消耗原随机流。无库存时随机领取返回 0，不消费随机数。
- 买入以点数支付，买价的十倍计入商店收入。卖出获得原价 90% 的点数，按一次交易总量截断，原价计入商店收入。商业商店结束访问时一次性更新余额和收支；重复关闭不会重复入账。
- 保留 AI 先出售不喜欢物品、点数不足 100 的额外出售、预算一半买卡一半买工具、机车/汽车优先与严格小于预算条件、其余六种工具固定顺序。普通 AI 商店不生成随机货架、不消费随机数。
- 保留原 AI 依据**卡片库存槽位置**查询出售偏好的错误，而不是自作修正为卡片 ID。
- 魔法屋的 12 个对象类别独立于 12 个效果。最大值类别包括全部并列玩家，排除不活跃者；土地与建筑类别同时计入普通土地和设施。性别按照原表的 1 男 / 0 女处理。
- AI 反复随机选有对象的类别；如果自己在对象里固定选择赠卡，否则抽 `rand()%11`，6 改成 7。这样转向有双倍机会，AI 不选拍卖。
- 魔法效果覆盖出售全卡、三次命运、免罪/嫁祸后拘留、停留计数、现金存入银行、脚下地产升降级、随机赠卡、转向、出售包含已装备交通的全部道具、住院、拍卖。魔法住院不额外执行受伤丢物逻辑。
- 拘留/住院前先更新仇恨；嵌套命运、选卡和拍卖由明确回调交给 Session。缺少必需回调时在任何变更前返回失败。魔法屋不能通过虚构“离开”选项跳过效果。

## 明确边界

原普通商店在全卡片供应已空时会除零；移植安全地返回空货架。交易接口拒绝不足点数、已关闭商店、库存不足和超出携带上限，不允许 UI 导致整数下溢。领取道具本身达到九个上限时，仍保留原随机领取函数返回所选 ID 的行为。

AI 的同价卡候选使用稳定排序。原版调用 Watcom `qsort`，价格相同的条目顺序尚未做原 EXE 对照，不能声称此处手牌顺序逐字节一致。商店与魔法的其它规则目前是原源码移植和合成测试，尚无完整原版 UI 事件差分证据。

## 验证

`services_tests` 覆盖：100 个 seed 的货架数量、加权抽取和随机调用数；有限货架与共享库存；买卖价格、批量出售一次截断、工具上限和商店收入只结算一次；原 AI 槽索引行为及零 RNG 消耗；财富/地产并列目标；多目标效果；缺失回调拒绝；三次命运；免罪取消、嫁祸重定向；停留高位回绕；已装备汽车纳入出售。

本机使用 C++20、严格 conversion warnings、AddressSanitizer 和 UndefinedBehaviorSanitizer 验证。原生 SDL 玩法回放另记录实际购买/出售、魔法选择及世界状态，不把本模块单测当作完整可玩性验收。
