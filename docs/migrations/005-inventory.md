# 005：卡片及道具库存规则

状态：**已迁移七个卡片库存函数、道具领取/消耗，以及出售道具的纯库存分支。** 商店交易、卡片效果、随机抽取、装备交通工具和画面刷新尚未迁移。

## 来源与明确边界

依据上游提交 `ec7d70e693059d1e781d9d1cc2ad7f36d360d39e` 的 `asm/rich4_card_utils.asm`、`asm/rich4_card_utils_2.asm`、`asm/rich4_tool_utils.c`、`asm/card.h`、`asm/tool.h`，并与用户原版 `rich4.exe` 的指令核对。

| 原版入口地址 | 新 API | 本次迁移范围 |
| --- | --- | --- |
| `0x441262` | `card_count` | 数出全部 15 槽中的非零项 |
| `0x44128f` | `cheapest_card` | 按槽顺序扫描，价格相同保留第一个 ID |
| `0x4412e4` | `receive_card` | 满手牌先归还最便宜卡，放入第一个空槽，扣共享库存 |
| `0x441343` | `consume_card` | 删除首个同 ID，后续槽向前移动，尾槽清零，归还共享库存 |
| `0x4413ad` | `has_card` | 全 15 槽查找；查询 0 的含义是有没有空槽 |
| `0x441ece` | `drop_half_cards` | 原始数量除二，每次取当前索引对应卡并消耗 |
| `0x441f21` | `sell_all_cards` | 归还全部卡片，返回价格总和；不自动入账 |
| `0x445a4d` | `receive_tool` | 每类上限 9，前八类检查并扣除共享库存 |
| `0x445aa2` | `consume_tool` | 数量非零才消耗，前八类归还共享库存 |
| `0x445b3f` 中 `traffic_method == 0` 分支 | `sell_stored_tools` | 归还/清空前十三类道具并返回价格总和 |

实现位于 `include/rich4/inventory.hpp` 和 `src/inventory.cpp`，使用 C++20 数组及固定宽度数值，没有主机指针大小、Win32、汇编或全局游戏状态依赖。

调用者传入一个玩家的 `CardSlots[15]` / `ToolAmounts[15]`、共享的 `CardSupply[30]` / `ToolSupply[8]` 以及价格表。卡片 ID 为 1..30，道具 ID 为 1..13。零是卡片空槽，不是可领取/消耗的卡片。价格表是输入，代码没有把商业游戏的表格/资源固化进去。

`consume_card`、`receive_tool`、`consume_tool` 额外返回明确的成功标志，方便新核心调用；原版函数没有定义返回值，因此差分测试只比较其状态变更。`drop_half_cards` 的布尔返回则对应原版的 0/1 返回值。

## 保留的原版细节

### 槽顺序与重复卡片

库存始终保留槽顺序，没有按编号或价格重新排序。价格相同取最早的槽。消费只删第一个同 ID，包括重复卡；无匹配时全部状态保持。

原版消费通过内部向前复制函数执行重叠内存移动。直接把它翻译成 C/C++ `memcpy` 会产生未定义行为，迁移版使用 `memmove` 表达相同结果。

满手牌领取始终先腾出位置，即使新卡更便宜也会接收；若腾出和领取的是同一 ID，共享数量先加一再减一，最终不变。

### 丢弃一半的顺序

原函数每次删除后继续递增槽索引，因此 `[A,B,C,D]` 删除 A，然后删除移动后的槽 1 中的 C，剩 `[B,D]`。五张卡只删两张。不能简单实现成「删除前一半」或「截取后一半」。

重复卡使行为更加细微：`[A,B,B,C,D,E]` 依次选择 A、B、D，删除 B 时仍然删除**首个同 ID**，最终为 `[B,C,E]`。测试固定了这个行为。

### 字节数量的环绕

库存计数是原版的无符号 8 位字节：归还到 255 后变成 0；领卡时从 0 扣除会变成 255。本次保留此行为，没有改成饱和计数或抛错。卡片领取函数本来就不负责判断共享库存够不够，选择可用卡片由更上层完成。

道具领取与卡片不同：前八类库存为 0 时直接不领取；每类持有数量达到 9 后不会扣库存。道具 9..13 不消耗共享池。归还和批量归还共享道具同样按字节环绕。

### 出售的返回值及外部效果

卡片出售返回每张卡的价格之和；道具出售返回 `价格 × 数量` 之和。两者都只变更库存，调用者负责之后如何使用返回的点数。迁移函数不自行扣现金、加点券、更新 UI 或模拟商店逻辑。

原版出售道具若已装备交通工具，会先归还对应车辆、重置交通方式/骰子并刷新人物。这段存在外部副作用，**不在 `sell_stored_tools` 范围内**。新 API 的名字刻意标明只出售存放中的道具；最后两个序列化槽（索引 13、14）保持原样，与原版仅循环前 13 类的库存分支一致。

## 非法输入的边界

原版对越界 ID 没有保护，可能访问表外内存。迁移版对索引型操作使用明确 ID 检查，并在操作前抛出 `std::invalid_argument`，不会部分修改库存。

`drop_half_cards` 特别要求非零卡片紧凑排列、后面才是空槽。带内部空槽的异常手牌可能使原版调用 `consume_card(0)`，继而写入共享卡片数组前一字节。迁移版拒绝这种输入，而不是把原版越界写入变成跨平台行为。其他卡片操作仍保留对合法 ID 的稀疏槽支持：领取填第一个空槽，消费按原顺序搬移，出售遍历所有非零槽。

这些是无效状态的显式安全边界，不宣称对原版越界内存破坏保持等价。

## 验证

`tests/inventory_tests.cpp` 包含独立语义测试：空手/满手、同价取首个、重复卡、缺卡、稀疏槽领取、丢半顺序、奇数张数、最大价格、库存环绕、道具数量上限、不同共享池规则、出售保留尾槽、非法输入原子拒绝。已用 Clang C++20 的严格警告、AddressSanitizer 和 UndefinedBehaviorSanitizer 运行通过。

原版对照适配器是 `tools/oracle/original_inventory.h`。它由既有的隔离原版 EXE 验证器调用，不加载正在进行中的游戏状态，也不修改原版磁盘文件。适配器设置合成输入，直接执行上述原版函数，记录返回值及卡片/道具数组变更。每个案例轮流选择四个玩家，额外检查其他玩家数组不变。

向量覆盖 11412 个案例：三组价格（原价格表、全部同价、覆盖字节范围的合成价格），0..15 张卡、六种含重复 ID 的排列、共享池 0/1/254/255、全部 30 种卡的稀疏槽，以及全部 13 类道具在 0/1/8/9/254/255 数量上的边界。合成价格仅改隔离进程的表字节并在捕获后恢复。原版内部复制函数已核对为自足的 `rep movs` 指令；道具出售仅走无需人物资源/UI 的 `traffic_method == 0` 分支。

向量文件 `golden/inventory.txt` 是本地产物，不加入 Git。其格式首行为 `rich4-inventory-v1`，第二行为案例数；每例依次为操作编号、ID 参数、原返回值、30 个卡价、13 个道具价、操作前后的卡槽/卡池/道具数量/道具池。未定义返回值的原版 void 函数统一记 -1，避免把寄存器残留当语义。

可独立运行合成测试，或附加本地原版向量作差分：

```sh
clang++ -std=c++20 -Wall -Wextra -Wpedantic -Wconversion -Wsign-conversion \
  -fsanitize=address,undefined -fno-omit-frame-pointer -g \
  -Iinclude src/inventory.cpp tests/inventory_tests.cpp -o .local/inventory-tests
.local/inventory-tests .local/oracle/latest/golden/inventory.txt
```

2026-10-05 已实际运行原版捕获及上述 ASan/UBSan 原生差分：**11412 个案例的返回值、卡槽、共享卡池、道具数量、共享道具池全部一致**。原版向量及其来源校验在 `.local/oracle/latest/manifest.json` 中记录，不依赖重写函数自行生成预期值。

此模块没有验证随机抽取、卡片效果、商店入账、装备交通工具或整局游戏行为。
